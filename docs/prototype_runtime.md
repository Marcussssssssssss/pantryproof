# PantryProof local-first prototype runtime

**Status** Consolidated revision for joint ratification by Tai Yong Xin and Leng Wei Heng, following `PANTRYPROOF_TAI_SHARED_REVIEW_CONTRACT_AND_PROTOTYPE_RUNTIME_REVIEW_01`, sections G–K. Implementation, changes to runtime pins and genuine execution require their applicable approvals.

## Runtime and user workflow

Use one local Windows Python backend and Tai's Inventory-First Sage V5 Android app on the same host's emulator. The app imports or captures a grocery receipt, previews and crops in its existing workflow, and submits a bounded PNG following an explicit **Process** action. The backend performs genuine OCR and B2, then the complete proposed seven-field method on a sufficient gate result. Android requests the [review response](review_contract.md), offers field review and separately confirms eligible inventory items using either confirmation mode. The same running backend then accepts a new receipt. The runtime keeps one active receipt pipeline at a time. A receipt must pass admission independently. Initial OCR runs on Windows and requires that backend. Later physical-device transport is a separate integration decision.

The component order is `ReceiptHttpService` → `LocalImageReceiptProcessorV0` → `NativeLocalImageProviderV0` and `SupervisedNativeLocalImageExecutorV0` → one retained LIVE gate → shared `extract_b2` → `run_proposed_receipt_v1` → Presentation V1 projection with optional review wrapper → Android. Reuse the existing cancellation and admission boundaries. Keep the request, OCR evidence, draft and inventory stages separate. Scope is Malaysian grocery receipts under the supported B2 grammars and applicable MYR representation.

### Four-hour maximum and renewal

- After successful preflight, capture the session opening time from the monotonic clock. The effective deadline is the earliest of `openedAt + 14,400 s`, any shorter approved session bound, and expiry of every applicable host-control authorization or resource attestation. Convert validated wall-clock expiries to conservative remaining durations once at opening. Reject future-dated, expired or invalid evidence. Later wall-clock changes cannot move the monotonic deadline later. A latch revokes admission immediately on invalidated controls, operator revocation or containment failure, even before the scheduled deadline.
- After authentication and before more body reads or decode, require the connection's full existing 115-second overall deadline to fit within the effective session deadline. Recheck controls and the remaining budget after acquiring the processor slot and before starting native work. The processing deadline plus its remaining response-write reserve must still fit. Within that processing deadline, require the approved minimum work window and full teardown reserve. When the check fails, close admission to that attempt and return empty `503`; refuse work with insufficient authorization rather than clipping its reserved teardown. Native dispatch and completion stay subject to the existing monitored checks.
- On expiry, revocation or violation, stop new admissions, invalidate the token, cancel active processing and suppress late results. Keep the necessary supervision running through confirmed cleanup or quarantine. A safety cleanup beyond an authorization cutoff is limited to containment, termination and teardown. It cannot authorize new OCR. Unconfirmed cleanup quarantines the runtime, and a replacement session requires independently confirmed cleanup before opening.
- Renewal is an explicit operator action. Close admissions, drain and confirm the old session's cleanup, validate refreshed applicable controls and open a new session with a fresh token and monotonic deadline. Keep the approved static build, runtime, model, gate and method pins. Refresh and verify the session evidence pin when it changes. The manifest and digest for the new session must bind that fresh evidence, while routine renewal under the same approved static configuration uses the approved renewal procedure without another full owner audit. Changes to static approved inputs require their applicable review. A renew action cannot extend an existing token or reuse expired evidence.

Implement session deadlines and evidence validation in the new prototype composition and scope. The current generated-only controls use a 600-second attestation age in `_confirmation_deadline`. Leave that path unchanged. Add prototype-specific validation of the independently approved evidence lifetime, capped at four hours per session, and retain existing live offline, launch, native resource and teardown observations at their current cadence. Depend on the evidence's actual validated expiry, even when it is shorter than four hours. Do not stretch the existing ten-minute development attestation to fill the prototype budget.

## One source gate and ordinary grocery layouts

The current T15 ratified gate requires a complete multiplier item above a unique footer total and can refuse ordinary layouts that B2 itself can parse, such as an item without a printed unit price. Propose `GATE_C_LIVE_GROCERY_V1` revision `1` within the existing LIVE gate module, with its own reviewed policy digest. Preserve original OCR validation, source/frame/ID binding, UTF-8, geometry and resource checks and evaluate once. Keep T15 policy identity and behavior scoped to T15.

For this policy, use the existing B2 visual-line grouping and helpers on the retained OCR tokens. Count positive cues only on unambiguous lines. A cue is either a complete MYR total anchor with valid amount, or an item-like line from the existing B2 grammar (`_looks_like_item` or the existing unmarked-whole item shape with valid description and MYR amounts). Exclude B2 control and column-header lines from item cues. If at least one positive cue exists, record `SUFFICIENT` and let B2 represent missing or unresolved fields and rows through its existing contracts. Do not use the gate to reconcile competing totals or ambiguous rows. Completed OCR with no positive cue records `INSUFFICIENT` and returns `FALLBACK_NO_UPDATE`. If no trustworthy layout can be formed from otherwise valid OCR, use the same insufficiency branch. Broken source binding, malformed OCR and actual grouping/execution errors remain technical failures. The producer must keep public reasons fixed and satisfy the existing privacy checks.

Keep B2 extraction and its field roles unchanged. A sufficient gate permits structured extraction. A sufficient result can still contain missing or unresolved fields, and it establishes neither receipt completeness nor grocery eligibility for research. A result with no eligible inventory rows cannot produce a stock write in either confirmation mode. Keep missing or unresolved values truthful, offer the existing recapture or manual paths when needed, and add no invented rows or field values. If verification artifacts are absent, use the explicit `NOT_READY` review path. Session 2 owns resource applicability, the fitted scorer, matching frozen calibration and the governed operating settings. Configuration invalidity blocks the verified composition. The runtime does not fit or recalibrate from user receipts.

If a caller times out or disconnects, the slot is still owned until cleanup or the native quarantine decision is recorded. Only the same completed, current request may publish a result.

Reuse the supervised executor, one native child per admitted attempt, Windows Job Object, one-process limit, private authenticated pipe ownership and request/frame binding. Provision the existing job memory, CPU-thread, scratch-byte, minimum-work and teardown-reserve values in the approved profile. Reuse the existing host-control monitor, pinned executable/dependency/model checks, offline observation and post-exit checks. Keep the development grant and exact-image check independent. Run the same native worker protocol and release the child after every attempt. ## Scratch, privacy and failure recovery

Hold byte payloads, decoded pixels, OCR, candidate and review evidence in request-scoped memory. Keep the existing bounded scratch controls. Require scratch absent at clean start, create it privately for the attempt, close process and pipe handles, verify the expected path and remove temporary files after the job exits. Discard request/response and observer references on completion, including cancellation. Keep raw image bytes, OCR text, tokens, credentials and user data out of normal logs and telemetry. Collect only fixed status, stage and elapsed time locally as needed for debugging. The generated research collector from T15 does not attach to ordinary processing. Any separate research export requires explicit data-use permission, a named custody location and approved retention. Android keeps the current source and evidence in app-private storage when needed for the draft/history with normal deletion controls. The backend does not persist user receipts or inventory.

| --- | --- |

| Active, unavailable or quarantined | `429` while a valid session's active attempt owns the slot. `503` when the grant is invalid, too little time remains for new admission, or native state is quarantined.
